Legacy scheduler actions behind the non-V3 dashboard are not required public-demo OWNER mutation flows. The V3 branch renders `SchedulerWorkspaceV3` and `SchedulerToolsV3`; only their listed historical export controls remain visible. Existing non-demo repository implementations and normal Firestore Rules must remain unchanged.

`ACTIVE_MUTATION_CALLSITE_INVENTORY=PASS`, `UNMIGRATED_REQUIRED_WRITE_CALLS=0`, `ACTIVE_DIRECT_BROWSER_WRITES=0` for the active set above. Demo branches return before legacy SDK writers; server-only public projection and primary audit adapters perform no browser write. The nine explicit demo Rules matches deny create/update/delete, independently verified with 27 direct SDK bypass attempts. Normal Rules and non-demo fallback writers retain their existing behavior.

Mutation retries retain at most16 opaque pending records (operation, UUID command ID, input digest, generation, original numeric revision). Successful unrelated actions do not discard ambiguous requests. No token or raw payload is persisted. All draft receipts omit the redundant draft ID so the128-byte result/256-byte receipt limits remain intact; the validated server-derived draft ID is recorded in the atomic recent audit event.

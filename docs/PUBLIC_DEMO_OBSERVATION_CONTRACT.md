# Public demo observation vs recovery evidence

`scripts/lib/demoObservation.ts` is the native, dependency-free schema/validator for `OBSERVATION_DOSSIER`, schemaVersion 1. Always pass exact external bytes and an independently approved SHA-256 to `parseObservationDossier`; do not use a bare JSON.parse result as validated evidence. The parser rejects duplicate/dangerous/unknown keys, unapproved resource identities, invalid UTC dates, future/stale observations, excessive capture windows and mismatched byte seals. It returns deeply frozen raw evidence plus separate semantic classifications. It never queries cloud, restores data or grants cutover permission.

Required top-level fields: schemaVersion, kind, qualificationSha, projectId, projectNumber, database, region, bucket, captureStartedAt, captureCompletedAt, observations. Identity is exactly the dedicated demo project/number/default database/region/bucket. Capture duration and age are each at most one hour. Each observation has resourceType, exact resource identity, state, observedAt and source (sanitized id, method, httpStatus). Present observations alone have value. Source IDs identify the read; never put credentials, personal data, reset URLs or private payloads there.

| State | Meaning | Source requirements | Value |
|---|---|---|---|
| OBSERVED_PRESENT | Read and validated allowed metadata | GET / 200 | Strict resource-specific fields |
| AUTHORITATIVELY_ABSENT | Exact optional Function/retention resource returned not-found | GET / 404 | Prohibited; no fake hash/document |
| UNREADABLE | Evidence unavailable, not confirmed absent | GET / allowed denial/failure status | Prohibited |
| NOT_OBSERVED | No authoritative read made | NONE / null | Prohibited |

Resource types: PROJECT, AUTH, FIRESTORE_RULES, STORAGE_RULES, FUNCTION, SCHEDULE, HOST_ASSIGNMENT, CONTROL, RETENTION, STORAGE_INVENTORY. Every identity is allowlisted; arbitrary URLs, projects, buckets, tenants or wildcard hosts are rejected. Exact Auth-domain and custom-host sets remain unchanged. Function source IDs/generations are metadata only, never archive hashes. Storage is metadata-only, exact demo PDF paths, complete pagination and unique object generations.

For CONTROL, value contains tenantId, representation, stateObservedAt, controlObservedAt and raw. `OBSERVED_LEGACY_IDLE` preserves generation, resetting=false, weekStart, lastResetAt, lease=null, leaseUntil=0, previousOwner=null. It must not contain synthetic phase fields. Interpretation is returned separately as `LEGACY_IDLE_COMPATIBLE`, not written into raw evidence. `OBSERVED_TARGET_OPEN` additionally requires actually observed phase=OPEN and controlPhase=OPEN. Capture times stay explicit; this dossier is not an atomic snapshot. Cutover comparison separately requires bounded read skew and matching recovery evidence. Unknown/destructive/non-idle control cannot become a valid idle observation.

The existing `maintenance/public-demo/live-baseline.schema.json` and `validateRecoveryBaseline` remain byte-identical. An observation dossier cannot satisfy VERIFIED recovery: missing preserved artifacts, backup, restore-drill and independent verification remain blockers. The previous live observations are historical partial evidence; this implementation performs no fresh cloud reads and must not re-date those files into a current dossier.

## Read-only cutover validator

`scripts/validate-public-demo-cutover-preconditions.mjs` accepts explicit path/hash pairs only. It has no deploy/apply/reset/update/patch/delete/rollback mode and never discovers a cloud target. Required identity arguments are `--qualification-sha`, `--expected-project`, `--expected-project-number`, `--expected-bucket`, `--expected-aliases`; they must match the exact demo boundary and current repository HEAD.

Evidence arguments: `--recovery`/`--recovery-sha256`, `--dossier`/`--dossier-sha256`, `--current-dossier`/`--current-dossier-sha256`, `--target`/`--target-sha256`, `--capabilities`/`--capabilities-sha256`, `--maintenance`/`--maintenance-sha256` (the last path is a built maintenance directory). An unverified recovery record produces `CUTOVER_RECOVERY_NOT_VERIFIED` before attempting unavailable downstream artifacts. This is an intentional FAIL, not incomplete evidence accepted as PASS.

The target manifest is DEMO_TARGET_PACKAGE/schemaVersion1: qualificationSha/contextSha256, exact demo identity/aliases, frontend/Firestore/Storage path+sha256 pairs, and exactly nine Function name/path/sha256/runtime/region/serviceIdentity entries. Paths are relative to the manifest directory; traversal, symlink escapes, missing/changed bytes and unreviewed Rules are rejected. The read-only context seal includes current source/packaging and validator/recovery inputs; it does not refresh any npm/Trivy exception fingerprint.

The capability record is a separately reviewed, externally hash-sealed LOCAL_CONTAINMENT_ATTESTATION with qualification/context SHA, broker and globalEntry=AVAILABLE_AND_TESTED_LOCAL, testEvidenceSha256, reviewEvidenceSha256 and observedAt. These are reviewed attestations, not self-generated runtime credentials or proof that deployment occurred. A caller must supply genuine independent test/review evidence; the static validator is not an oracle that can establish a restore drill or test execution from metadata alone.

Both dossiers, strict VERIFIED recovery, revisions/schedules/aliases/generations/control/retention/Storage, actual target bytes, maintenance bytes and capability/context are compared. The current capture must follow the prepared capture, have a distinct seal, and identify genuinely later reads with non-reused source IDs. Read provenance timestamps may advance without creating false control-state drift; raw control facts must stay identical. Source IDs identify a particular read/capture, not a reusable resource URL. Files/context and target bytes are rechecked around the decision. Even complete synthetic/local evidence returns only LOCAL_PRECONDITIONS_VALID with deploymentAuthorized=false. Recheck immediately before a separately approved window; no read-only PASS remains durable authority after external state changes.
